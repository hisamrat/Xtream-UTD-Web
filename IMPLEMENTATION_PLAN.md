# Xtream UTD Implementation Plan

Build a Next.js App Router product-catalogue website for Xtream UTD using the approved `design-reference` screens as the source of truth. The app keeps product terminology throughout, uses the sample product dataset, and centralizes all unverified business/contact details as editable placeholders.

## Stages

1. Scaffold the app with strict TypeScript, linting, tests, and a token-based design system.
2. Validate and normalize the sample product dataset.
3. Build the shared shell, header, mobile menu, search overlay, theme support, and bottom product switch.
4. Build the catalogue grid, product cards, search, filters, sorting, and responsive states.
5. Build product details, gallery placeholders, related products, recently viewed products, and inquiry flow.
6. Build the 3D product world with drag, zoom, click-vs-drag protection, fallback, and reduced-motion support.
7. Build About, Contact, product not-found, and offline states.
8. Verify lint, typecheck, tests, build, and local responsive behaviour.

## Editable Placeholders

Real product photography, logo assets, Facebook/Messenger URL, WhatsApp number, phone, email, exact location, business hours, delivery charges, and return/replacement policy remain placeholders until verified.
